# JobScope 可验证研究 Agent

用户授权直接升级，以AI Agent岗位面试中可以实际演示、解释取舍、复现评测为验收标准。本次保持个人本地工作区，不增加云端多租户或自动投递。

## 选择

只补同义词不能解决统计、追问及版本问题。直接套通用自主Agent会扩大工具面、成本与不确定性。本次采用有预算的研究工作流：结构化问题计划→受范围约束的查询工具→证据覆盖检查→最多一次补充检索→带引用回答。模型负责语义理解与表达，数据库负责金额过滤和准确计数。公开执行事件，不展示模型内部思维链。

## 模块

- `research/index.py`：SQLite FTS5持久分块索引、岗位当前版本投影、薪资事实、索引版本与增量更新。原始证据不可变。中文双字词与英文词索引；查询不读取全部原文。正文片段记录字符偏移及页码。
- `research/query.py`：类型化QueryPlan；本地领域概念扩展；可配置模型计划；只从服务端用户历史还原追问。模糊薪资阈值默认按区间下限，返回明确口径。客户端与模型不能扩大授权范围。
- `research/retrieval.py`：FTS BM25、可选真实向量召回、RRF融合、证据版本去重、来源/公司覆盖和字符预算。无向量配置时标明lexical模式；向量服务失败显式降级。零相关证据拒答，无法把随机记录当命中。
- `research/providers.py`：有超时、响应校验、批次和缓存的兼容模型/embedding接口。真实向量绑定模型与文本hash，不使用随机向量或词项hash冒充语义向量。
- `research/tools.py`：只读、参数化SQL的薪资聚合与岗位筛选。CNY月薪、区间下限/上限、招聘报价与实际工资分离；未知、不支持币种、最高几薪不隐式年化。返回全量符合条件数量和有限样本及来源。
- `research/agent.py`：有界编排、澄清与降级、工具结果上下文、运行ID/耗时/策略/调用/覆盖/引用的持久执行记录。不授予模型任意SQL、浏览器或文件执行权限。
- 前端：回答下折叠展示检索过程、工具统计、降级原因与运行ID；可以核对统计口径及证据出处。
- `evals`：版本化人工标注场景和独立干扰材料，原始关键词基线、BM25及混合策略对比。报告Recall@k、MRR、无结果、范围泄漏、薪资准确率与延迟；与自动测试分开。合成集不冒充真实用户评测。

## 数据与边界

公司范围精确匹配；岗位范围限当前岗位和同公司非岗位材料。全局允许全部本项目证据。所有工具在SQL层应用相同scope，并再次校验输出。索引只暴露当前岗位快照，历史仍可在来源档案浏览。无独立实际工资样本时明确未知。相似公司不自动合并，含糊公司需澄清。

检索候选最多80，输出最多8份来源，字符上下文上限24000。计划模型最多一次，补充检索最多一次，回答模型一次；网络错误不无限重试。统计工具不受检索top-k影响。

无模型时运行确定性计划与工具，显示结构化查询/资料检索模式。无embedding时BM25可工作，但不声称通过语义检索验收。外部模型质量、embedding真实质量只有在配置对应服务并实际运行后才可宣称验证。

## 验收

工资→薪资别名召回、后续“那乙公司呢”保留工资意图且换主体、公司范围无法被模型/材料扩大、完整JD优先旧摘要、零匹配为空、相同正文去重、PDF后页定位、增量更新可重建、金额阈值统计无top-k截断、实际工资不冒充招聘薪资、模型计划错误降级、embedding维度与缓存校验、可追踪执行、基线对比和UI验证。
