# JobScope 渠道与模型选择

用户要求：渠道选择或自定义；OpenAI / Anthropic 协议；模型搜索与连接测试。

## 交互

保留独立的对话和向量设置。API 模式显示渠道按钮，渠道预填协议、服务地址及参考模型。服务商地址折叠进高级设置，自定义渠道展开地址输入。先填密钥，再获取账户模型列表，在同一输入框搜索或直接填模型 ID，点击结果选用。测试不保存，保存后下次请求生效。

在线列表与渠道预设明确区分。列表失败或为空允许手动 ID；实际权限以测试为准。列表有滚动高度及展示上限，不撑长页面。表单操作期间锁定，修改连接参数清除旧列表和测试状态。

## 后端

渠道目录 /api/settings/channels；草稿获取列表 /api/settings/models/discover；原设置读取、保存及测试 API 保持兼容。保存 channel、protocol，并为旧配置补 custom/openai。环境变量支持 JOBSCOPE_LLM_PROTOCOL。

共享 model_transport 负责端点推导、认证头、消息格式和响应提取。OpenAI 使用 Bearer、Chat Completions；Anthropic 使用 x-api-key、anthropic-version、顶层 system 及 Messages 文本块。查询规划、资料问答、适配分析、连接测试均走同一适配器。向量接口继续为 OpenAI Embeddings。

密钥绑定规范化后的实际端点；同地址 Base URL 与完整端点等价，协议变化或地址变化需要新密钥或显式清除。保留原有完整端点，包括不带 /v1 的根级端点。旧配置和请求内快照继续生效。

## 验证

后端覆盖渠道、列表去重、不保存草稿、失败脱敏、旧地址兼容、两协议认证与请求格式、实际规划/问答/适配分析、异常内容块。浏览器覆盖预设、协议、在线模型搜索选择、未保存测试、保存后问答、密钥保留/清除、手机布局。

使用本地假服务验证协议与交互；无真实渠道凭证，未验证真实账户权限与各渠道线上可用性。预设为可编辑默认值，参考模型不承诺在用户账户可用。
