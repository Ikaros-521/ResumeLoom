# JobScope 第一版实施计划

> **For agentic workers:** 使用 subagent-driven-development 执行独立实现任务，主代理负责接口契约、集成、真实数据源验证和最终检查。

**Goal:** 交付可以本地启动的岗位情报应用，支持真实接口采集、证据存储、简历匹配和基于资料的聊天。

**Architecture:** 当前仓库内建立独立 `jobscope/` 应用目录，在 `codex/jobscope` 分支开发。Python/FastAPI 提供接口，SQLite 保存证据、岗位与采集状态，React/TypeScript 提供界面。HTTP API 优先；真实 Chrome 持久会话监听作为 BOSS 等来源的补充路径。

**Tech Stack:** Python 3.12、FastAPI、httpx、SQLite、PyYAML、DrissionPage（浏览器可选依赖）、React、TypeScript、Vite。

**Spec:** `docs/proposals/2026-11-07-jobscope-design-draft.md`。用户已回复“继续”，按当前独立本地应用方案实施，不再重复要求设计确认。

## 文件与接口契约

- `jobscope/backend/jobscope/`：后端模块，`main.py` 导出 `create_app(data_dir=None)` 与 `app`。
- `jobscope/backend/tests/`：pytest，使用临时目录，测试不访问真实平台。
- `jobscope/frontend/`：React 项目；生产构建目录 `dist/` 由后端挂载，开发时 Vite 代理 `/api`。
- `jobscope/scripts/`：真实接口验收、浏览器会话与启动辅助脚本。
- `jobscope/README.md`：安装、启动、模型配置、登录与验证边界。
- `jobscope/.data/`：默认本地数据目录，版本控制忽略。

API 均返回 JSON；错误 `{detail: string}`。时间使用 ISO 8601 UTC。

1. `GET /api/health`：`{status, model_configured}`。
2. `GET /api/sources`：`{sources:[{id,name,transport_mode,status,description}]}`。
3. `POST /api/collect`：`{source,query,location?,limit?}`，返回 `{task,jobs}`。首版同步、有请求超时，任务持久化；不声称支持分布式队列。source 为 `remotive`、`boss` 或 `cninfo`；cninfo 采集公司公告，不返回岗位。
4. `GET /api/tasks`：`{tasks:[{id,source,query,status,message,created_at,count}]}`。
5. `GET /api/jobs?q=&location=`：`{jobs:[{id,title,company,location,salary,url,source,updated_at,description,evidence_ids,tags}]}`。
6. `GET /api/jobs/{id}`：`{job,evidence:[...],company_evidence:[...]}`。
7. `POST /api/import/job`：用户材料 `{title,company,location?,salary?,url?,description}`；返回 `{job}`，明确 source 为 `user_import`。
8. `GET /api/evidence?company=&q=`：`{evidence:[{id,title,url,source,kind,company,text,collected_at,published_at,content_hash}]}`。
9. `POST /api/evidence`：`{title,url?,company,kind,text,published_at?}`，保存用户资料；返回 `{evidence}`。
10. `GET /api/resume` 与 `PUT /api/resume`：`{text,format}`，format 为 `text` 或 `facts_yaml`；保存后返回 `{text,format,revision}`。
11. `POST /api/analyze`：`{job_id}`；返回 `{job_id,resume_revision,score,coverage,method,requirements:[{requirement,status,evidence,dimension}],strengths,gaps,questions,salary,company_summary,evidence_ids}`。覆盖不足 score 为 null。method 明确为规则辅助或模型分析，不能伪装语义能力。
12. `POST /api/chat`：`{message,job_id?,company?,history?:[{role,content}]}`；返回 `{answer,mode,citations:[{id,title,url,excerpt}]}`。无模型时 mode 为 `evidence_search`，明确只提供检索摘录；有模型时调用可配置的兼容接口并验证引用存在与范围。
13. `GET /api/browser/status`：`{installed,running,message}`；`POST /api/browser/start` 启动专用本机 Chrome；`POST /api/browser/collect` 使用用户已登录的 BOSS 页面触发请求、采集响应。返回 `{task,jobs}`。
