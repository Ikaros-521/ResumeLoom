# ResumeLoom 纯 Skill 套件实施计划

日期：2026-11-06。用户已选择纯 Skill 套件；按已讨论的五步链与事实门禁实施。

**目标：**交付可单独调用的五个原子 Skill、一个编排 Skill，以及文件模板与虚构端到端样例。

**结构：**`skills/resume-{dig,tailor,humanize,audit,apply}/` 各自携带必要说明与输出模板；`skills/job-pipeline/` 负责顺序、文件版本、退回与恢复。共享状态为用户工作目录中的文件，不依赖聊天历史、LLM 厂商或代码运行时。

**技术范围：**Markdown 指令与模板。无应用代码、算法评分器、浏览器驱动或 Web 应用。apply 在宿主具备网页操作能力时填表，否则输出离线填写清单。

- [x] 基线：用含事实冲突、JD 指令注入、缺失筛选答案、过期审查的场景演练，保留实际观察。
- [x] dig：建立带来源、确认状态、版本与稳定 ID 的事实档案；验证不采信未知数字。
- [x] tailor：建立 JD 要求映射、简历正文与事实侧录；验证不注入未掌握的技能。
- [x] humanize：只修改表达并更新侧录；验证不扩大职责、不损伤技术关键词。
- [x] audit：事实门禁、ATS 轨、表达轨分开；验证 Markdown 审查不冒充实际 PDF 解析。
- [x] apply：记录已填、待处理和实际操作证据；验证无浏览器时不声称已填，不提交。
- [x] job-pipeline：串行调用、精确版本绑定、有限退回与失效传播；验证过期报告不可放行。
- [x] 交付：README、六份 Skill、各阶段模板、完整虚构样例、场景验证记录。
- [x] 校验：运行 Skill 官方格式检查、相对链接检查、样例 ID/版本/追溯关系检查，进行独立行为演练。

验收以实际产物和检查输出为准。行为演练只覆盖记录的场景，不宣称适配所有宿主或真实 ATS。代码仓库不保存真实候选人资料；真实任务产物放在被 Git 忽略的 `runs/`。
