# 知根 JobScope：求职情报与简历适配 Agent 设计草案

日期：2026-11-07。状态：用户已确认继续，第一版本地应用已实现；实际交付范围以 `jobscope/README.md` 和 `docs/validation/jobscope-live.md` 为准。下文保留设计目标，其中完整平台覆盖、后台调度等目标不代表全部已经完成。已根据用户补充更新采集要求：接口优先，浏览器兜底；浏览器需考虑真实环境、长期会话及被识别的风险，不能直接采用默认临时 Playwright 环境作为生产方案。

## 目标与项目位置

用户输入岗位关键词、城市、薪资等偏好，或提供岗位链接。系统采集岗位与公司资料，结合个人简历，回答“是否适合我、值得不值得去、有哪些证据、还需要问清什么”。

建议开发为独立、个人本地使用的应用。与 ResumeLoom 通过文件契约连接，读取其 `facts.yaml`，并可输出岗位 JD 和研究报告。当前目录只保存本草案；正式代码位置在设计确认后确定。既有 ResumeLoom 是纯 Skill 项目，不把它直接改造成后端。

首版默认中文、中国大陆招聘场景、单用户本地部署。默认不需要云端账号系统。不把自动投递、联系招聘方或批量建立员工个人档案纳入首版。

## 方案比较

| 方案 | 优点 | 代价 | 建议 |
| --- | --- | --- | --- |
| 独立本地应用、持久证据库、受约束的研究 Agent | 搜索、历史比较、简历匹配和聊天使用同一份数据；能验证出处 | 需要后端、采集器和前端 | 推荐 |
| 在 ResumeLoom 中增加研究 Skill | 启动快，复用现有宿主工具 | 批量刷新、历史快照和交互依赖宿主，难以形成稳定的数据产品 | 适合先体验流程 |
| 多用户云端 SaaS | 跨设备、集中调度 | 登录态隔离、部署、租户权限和成本显著增加 | 后续再评估 |

## 首版闭环

1. 配置求职偏好，导入简历 Markdown、纯文本或 ResumeLoom 事实档案。PDF/DOCX 提取作为后续接入项；首版可由用户先导出文本。
2. 输入关键词检索岗位，或导入岗位链接、网页文本、结构化数据。
3. 保存岗位快照，识别招聘主体与用工主体，建立公司关联。
4. 收集公司官网、公开公告和可访问的招聘资料，形成公司档案。
5. 输出薪酬分析、用工与经营信号、匹配依据、缺口及面试核实问题。
6. 围绕当前岗位、公司或比较集合聊天，每项外部事实能回到具体证据。
7. 手动刷新并比较历史快照；采集失败或资料不足时明确显示状态。

首版的在线验收以一个实际跑通的岗位来源、一个公司公开来源为最低闭环。优先评估 BOSS 直聘和企业官网；平台尚未通过访问验证前，不承诺已支持。离线导入用于开发回放和不可访问资料的补充，不能冒充已完成在线采集。

- 巨潮资讯：https://www.cninfo.com.cn/
- BOSS 直聘：https://www.zhipin.com/

每个连接器先输出能力状态：可搜索、可取详情、需登录、需人工验证、暂不支持。记录实际测试时间和失败原因。公司招聘官网按具体网站接入，不宣称一套规则能覆盖所有官网。

允许使用用户授权的登录浏览器会话。若需要 Cookie 或浏览器存储状态，提供本地导入入口和所需域名说明，再请用户操作。凭据不进入聊天、版本库、报告、模型上下文或日志；本地凭据采用系统凭据保护机制，不仅依赖 Git 忽略。

必要时使用 REA 分析实际可访问页面的请求、响应与字段映射。遇到登录失效、验证码或访问限制时记录并等待用户操作，不承诺 Cookie 能解决所有限制。

## 采集策略：接口优先与真实浏览器会话

这是用户明确提出的要求。连接器采用以下优先级，但具体端点需要实际取证，不能凭空猜接口：

1. **官方或公开接口**：优先使用有文档、开放或已获访问权限的查询接口，以独立 HTTP 客户端采集结构化数据。
2. **经页面验证的站点接口**：在正常访问页面时观察查询请求，确认参数、分页、响应字段、认证和有效期；验证独立客户端可稳定调用后，再提取为接口连接器。只覆盖当前账号有权限访问的资料。
3. **浏览器触发、响应采集**：接口依赖页面运行状态或浏览器会话时，由真实浏览器正常搜索、翻页，监听与当前任务有关的响应，优先解析 JSON。浏览器负责访问环境，数据层处理结构化响应。
4. **页面提取**：没有可用结构化响应时，再按页面结构提取 DOM；桌面界面操作保留为确有需要时的人工辅助路径，不作为默认批量采集方案。

接口化不等于复制 URL 和 Cookie。认证还可能涉及 CSRF、临时令牌、请求来源、存储状态和服务端会话；普通 HTTP 客户端与浏览器的网络协议表现也可能不同。独立 HTTP 请求、浏览器上下文请求和页面自身发起的请求分别验收，不能把共享 Cookie 等同于共享完整网络环境。Playwright 的 `browserContext.request` 与浏览器上下文共享 Cookie，但不能据此声称其请求具有浏览器页面的完整网络特征。

### 浏览器环境与会话

- 优先使用本机正常安装的稳定版 Chrome，Edge 作为验证候选，默认有界面运行。首次登录由用户完成；后续使用项目专属、长期保留的配置目录，不每个任务重建临时环境。
- 使用当前设备真实的操作系统、浏览器版本、语言、时区和显示配置。优先保留浏览器自然值；不在每次任务中随机切换 UA、屏幕参数等造成自相矛盾的组合。
- Chrome 136 起，远程调试开关需要指向非默认用户数据目录。项目不能假设能够直接连接用户日常主配置目录；专用目录建立后单独登录、持久复用，不默认复制用户主浏览器资料。
- 持久目录能够保留浏览器状态，但不保证登录永久有效。Cookie 导入是备选；Cookie 不足时说明需要用户在项目浏览器重新登录，不反复索取同一份无效 Cookie。
- 同一站点和会话串行调度，缓存重复查询，列表分页保存游标，增量更新详情。尊重服务器明确的重试等待信息，出现验证码或访问限制时暂停该站点任务，避免反复重试扩大失败。
- 调试连接只允许本机访问，配置目录和浏览器存储按凭据处理。网络监听仅采集目标任务需要的响应，归档前过滤令牌、个人联系方式等敏感信息。

真实浏览器、CDP 接管、持久会话和低访问频率都不构成“不会被检测”的保证。检测还可能结合账号历史、流量模式及服务端信号。验收应记录实际访问结果，不能把“无 WebDriver”或安装某个 stealth 插件作为通过标准。

### 工具候选与选择

| 方案 | 本项目用途 | 需要验证的代价 |
| --- | --- | --- |
| HTTP 客户端 | 独立调用已验证接口，分页、缓存和断点恢复 | 会话和令牌更新；不能假设等同浏览器请求 |
| DrissionPage + 本机 Chrome | 首个浏览器采集候选，Python 集成，连接长期会话并监听返回数据 | 目标站点实际成功率、版本兼容、维护状态与许可证 |
| Playwright + 本机 Chrome/CDP | 对照候选、已有浏览器连接、页面交互和应用自身 UI 测试 | 官方说明 CDP 连接能力保真度低于 Playwright 原生连接；实际兼容性需测 |
| nodriver/CDP | 前两种浏览器方案存在可定位问题时的备选 | 网络事件封装、维护成本与版本兼容；不能仅凭工具宣传认定更隐蔽 |

暂定先验证 HTTP + DrissionPage 的组合，同时保留 Playwright 适配接口；这不是已完成选型。不同数据源允许采用不同策略，但共享任务、会话引用、证据和错误状态契约。首版不同时维护三套浏览器引擎，也不把更换工具当作采集成功的依据。

### 接口调查与连接器契约

对每个目标站点建立取证记录：来源页面、请求方法、路径、非敏感参数、响应结构、分页语义、会话依赖、实际验证时间及异常样例。通过 REA 或浏览器网络事件取得的观察与推断分开记录。请求样本脱敏后才可保存到代码仓库；认证字段仅引用本地会话，不写进样例。

连接器声明 `transport_mode`（`http_api`、`browser_response`、`dom`）、`session_ref`、访问能力和验证时间。会话由独立管理器维护，连接器不能把完整 Cookie 返回给 Agent。

任务状态包括等待、运行、完成、需登录、需人工验证、退避等待、不支持和失败。HTTP 200 但返回登录页、验证页或异常结构也应识别为失败状态；不能转换成“查询成功但零条数据”。

### 采集验收

先对选定的一个站点做正常浏览基线，再验证独立接口、浏览器响应采集和必要的页面提取。样例覆盖关键词搜索、翻页、详情、重复采集去重、进程重启后的会话恢复、认证失效及异常响应。恢复与异常路径允许用脱敏回放测试，真实在线能力必须有实际访问记录。

记录完整率、重复率、成功及失败次数、登录或验证中断、请求耗时和可用字段；少量测试只能说明该时间和环境中的结果，不能作为长期成功率承诺。没有实际试验前，不声称 DrissionPage、nodriver 或 CDP 比 Playwright 在目标站更难被检测。

## 证据契约

每条证据至少有：稳定 ID、来源 URL、标题、发布者、采集时间、内容日期或报告期间、可定位摘录、内容哈希、证据类型及关联主体。页面未标注日期时明确为未知，不能用采集时间代替发布时间。

证据类型分为正式披露、企业自述、招聘信息、员工自述、媒体报道、用户材料。来源类型不是真实性保证。不同口径、不同时间或相互冲突的证据并列保留；转载同一原文不能算成多个独立样本。记录内容日期、地域和目标实体匹配情况，解释为何采用或排除某条证据。

公司实体保存法定名称及可得的统一社会信用代码；品牌、集团、子公司和外包用工关系另建映射。证据不足时标记待确认，不把母公司利润直接归到招聘子公司。

保存岗位原始快照与清洗版本。刷新保留历史，不覆盖旧证据。证据更新或简历修订后，关联报告标记需要重算。

## 分析与展示规则

### 薪酬

分别展示招聘区间、员工自述样本、固定年薪、浮动奖金和股权。只有明确保证的薪资月数才能计入保证现金年薪；“最高 16 薪”等表述不能当作保证 16 薪。

不从税前工资推算“实际到手”而忽略税务、社保和个人差异。可比样本不足时只展示样本及限制，不生成所谓实际薪资平均值。首版只对币种、城市、岗位族、职级和时间可比较的样本做描述统计，并显示有效样本数；少于五个独立样本时不提供市场代表性区间。五个样本也不意味着具备统计代表性。

### 员工、业绩与发展

员工情况关注员工总数及期间、团队线索、招聘趋势、公开工作体验。评论不等于全体员工意见；观察不到在招岗位也不等于公司裁员。

业绩指标保留报告期间与会计口径。发展前景输出支持信号、风险信号、未知项和条件化判断，不预测公司必然增长或个人岗位必然安全。没有公开财报时显示缺失，不用模型常识编造业绩。

### 简历适配度

首版维度：技能 35%、经历与职责 30%、行业或业务经验 15%、地点薪资等求职偏好 20%。权重可配置，规则版本随报告保存。这是辅助比较指标，不是录用概率。

要求逐项关联 JD 原文和简历事实 ID，输出满足、部分满足、明确不满足、未知。明确硬性条件单独呈现。未知不等于不满足，也不能按满足处理。

同一维度内的要求首版等权。已判定要求按满足 1、部分满足 0.5、不满足 0 计算该维度得分；未知要求不进入已判定得分分母。维度覆盖率为已判定要求数量除以该维度要求总数，整体覆盖率按维度权重汇总。整体覆盖率低于 60% 时不展示总分，只显示逐项映射和待确认问题。整体分数只在维度证据可用时归一化，并列出被排除的维度，不能跨不同覆盖率直接排名。没有要求的维度为不适用，其权重从整体覆盖率和总分中同时排除。

ResumeLoom 的已确认事实可作为用户认可的个人材料，但不是外部认证。其他简历文本提取的陈述先作为用户提供材料；模型推断不能升级为确认事实。建议必须指出已有依据、能力缺口、待核实条件和下一步行动，不能建议虚构经历。

## 技术组成

建议 Python + FastAPI 后端、SQLite + FTS5 检索、React + TypeScript 前端。先完成本地全文检索和结构化过滤；中文检索需做实际分词验证或回退到可用的检索策略，不能默认英文分词配置适合中文。嵌入模型和重排留出接口，只有实际检索评测显示需要时才增加。

| 模块 | 职责 | 主要接口 |
| --- | --- | --- |
| 连接器 | 搜索、读取详情、公开资料采集、登录态状态 | `search_jobs`、`fetch_job`、`fetch_company_source` |
| 会话管理 | 专属浏览器目录、登录恢复、域名绑定与本地凭据保护 | 获取会话引用、查询状态、人工恢复 |
| 采集任务 | 限速、超时、重试、去重与任务进度 | 创建任务、读取任务、人工恢复 |
| 证据与实体库 | 来源存档、主体关联、口径、版本 | 保存证据、查询主体、读取快照 |
| 检索 | 主体、岗位、日期与来源过滤，全文召回 | `search_evidence`、`read_evidence` |
| 分析 | 薪资归一化、简历要求映射、公司信号汇总 | 生成版本化报告 |
| 聊天 Agent | 在选择的资料范围内调用检索与分析工具 | 带引用的回答、资料不足状态 |
| 本地界面 | 岗位搜索、公司档案、简历、比较与聊天 | 与本地后端交互 |

模型供应商通过配置适配。采集、解析、检索、归一化与算分不依赖模型自由执行；模型负责受约束的结构化抽取和说明。默认单个工具调用 Agent，无需多 Agent 编排。

采集任务保存在数据库，重启可恢复；首版采用单个本地 worker，不引入分布式队列。模型失败不影响已采集证据保存，重试只重跑失败阶段。缓存依据输入快照、模型及规则版本失效。

## 聊天行为

支持“为什么适合我”“比较两家公司”“薪资是否有水分”“应该问面试官什么”等问题。每轮限定当前岗位、公司或显式选择的比较集合，也可明确发起新检索。

检索范围、实际使用的证据 ID 和生成报告版本可追踪。外部事实必须引用已存证据，引用能展开原文与 URL。模型输出先校验引用存在且属于当前允许范围；系统不能仅因 ID 存在就声称语义已验证。用人工标注的样例检查回答是否真的被引用摘录支持。

没有证据时明确回答未查到。新采集需通过明确工具调用，不能声称已做并不存在的搜索。网页与评论只作资料，不能作为给 Agent 的操作指令。聊天不能读取凭据，也不具备任意文件读取、任意命令执行或无限制网络请求能力。

## 故障与本地数据

- 采集超时或限流：有上限的退避重试，保留已经取得的结果。
- 登录过期或验证码：任务进入需用户操作状态，不循环轰炸站点。
- 内容结构变化：保存错误类别和受控调试资料，不把解析失败当成零岗位或零收入。
- 模型不可用：仍能查看证据与结构化数据，分析任务显示失败及可重试状态。
- 简历、Cookie、数据库和原始页面存到忽略版本控制的本地数据目录；对原始响应里的敏感字段做过滤。
- 服务默认仅监听本地地址。链接采集限制 HTTP(S)，阻止内网、回环及本机元数据地址，包括重定向后的目标；浏览器自动化使用独立配置目录。

## 分阶段交付与验收

### 阶段一：一条可核验的端到端链路

完成一个实际可用的岗位来源、一个公司来源、持久证据库、简历导入、适配分析和带引用聊天。提供虚构样例和显式区分的离线回放，方便无 Cookie 或无模型密钥时验证页面与存储流程；无模型配置时不得把固定模板标成模型聊天成功。

验收必须运行实际搜索与详情读取；记录访问时间、返回数量、来源链接、失败限制。实际平台无法接入时报告阻塞，不能用演示数据宣称在线能力完成。

### 阶段二：拓展数据与历史比较

再接招聘平台、登录态薪酬及评价来源，完善财报文件解析、实体消歧、岗位变化、跨公司比较与用户控制的刷新频率。每个来源单独验收，不能一次笼统宣布全部支持。

### 关键验证样例

1. 同名公司、品牌与子公司不能误合并。
2. “13–16 薪”、实习日薪、税前月薪及奖金未保证的情况计算正确。
3. 同一评论转载多次不增加独立样本数。
4. 缺少财报或实际工资样本时不编造结论。
5. 简历未知项、硬性条件不满足和覆盖率不足呈现正确。
6. 岗位页面里的指令注入不能触发操作或读取私密数据。
7. 引用必须属于当前资料范围，且抽样检查支持对应陈述。
8. 登录失效、页面结构变化、限流和任务中断均有可见状态与恢复路径。
9. Cookie 不出现在日志、报告、模型请求或 Git 跟踪文件里。
10. 从实际岗位检索到公司资料、匹配报告和追问，走通一次真实闭环。
11. 验证 HTTP 200 的登录页和验证响应不会被当成有效数据；分页、重启与会话失效后无静默漏采。
12. 为选定站点记录接口直调与浏览器路径的实际访问证据，确认使用策略与回退原因。
