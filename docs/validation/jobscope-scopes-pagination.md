# JobScope 对话范围、分页及完整岗位职责验收

日期：2026-11-07。沿用已确认的绿色、中性灰 unslop 设计，使用 Product Design audit 检查实际页面后实施。

## 已实现的行为

1. 公司资料库把“来源档案”和“公司对话”分成标签。公司对话锁定精确主体；品牌、集团、子公司不自动合并。切换公司新建会话，范围提示始终可见。同公司对话在来源/对话标签及主导航间切换时保留。
2. 全局对话使用独立导航，可检索全项目已保存的岗位和公司证据，引用标明公司及来源。公司名称参与相关度排序。每次回答使用检索片段，不能当作全库穷尽统计。
3. 服务端绑定会话 ID 与范围，读取服务端历史，忽略客户端传入历史。不同公司、岗位和全局会话不能复用 ID。切换范围后才返回的回复不会进入当前会话，新建会话也会丢弃旧请求结果。
4. 岗位默认20条/页，来源档案、岗位证据及任务记录默认10条/页。SQL先过滤、计数，再执行LIMIT/OFFSET；越界页收敛到末页。概览只返回有限预览，完整证据另走分页接口。
5. 来源档案桌面端分列展示公司与资料，手机端堆叠。上下均有分页。岗位列表与JD正文使用有限滚动区域。标签支持方向键、Home、End及明确选中状态。
6. BOSS岗位区分列表摘要与完整正文。完整正文保存来源、采集时间及不可变证据；后续列表更新不会覆盖已有完整JD。摘要状态不能进行适配分析。单条和后台批量补采均可用，逐条保存、跳过完成项，登录或验证时暂停。

## 真实采集与限制

已有299条BOSS岗位，使用已登录项目Chrome读取各自详情页的可见正文。读取页面URL必须与已保存岗位身份一致。公司介绍保存为`company_statement`，明确属于招聘平台展示/企业自述，不作为独立核验的实际薪资、营收、员工总数或发展结论。

真实补采完成：299/299条岗位有完整JD（先单条读取1条，再批量成功298条，失败0条、待补全0条）。逐条核对299条正文均具有同岗位URL、同公司及完整正文的证据快照。正文长度62–2874字符，中位数720字符；短JD按页面可见原文保存，长度不代表招聘信息充分。共1160条来源档案，其中897条岗位版本快照、263条平台公司自述，覆盖273个公司品牌名称。旧列表摘要保留在证据档案中，完整JD另外保存快照；归档条目总数因此大于岗位数。没有删除既有证据、发送招聘消息或自动投递。
