# 知根 JobScope

本地岗位情报工作台：采集岗位和公司公开资料，保存来源，再结合简历生成适配分析并围绕资料提问。独立应用位于本目录，与仓库原有 ResumeLoom Skill 通过 `facts.yaml` 连接。

## 安装与启动

需要 Python 3.11+、Node.js 20+。在 Windows PowerShell 中运行：

```powershell
cd E:\Github_Pro\ResumeLoom\jobscope
.\start.ps1 -Install -Browser
```

首次安装后，日常启动：

```powershell
.\start.ps1
```

打开 http://127.0.0.1:8765 。服务仅监听本机；不应将此个人版本直接暴露到公网。默认运行数据在 `jobscope/.data/`，包括数据库和独立浏览器配置，不提交 Git。

其他系统可手动启动：

```bash
python -m venv .venv
# 激活环境后：
python -m pip install -r backend/requirements.txt
cd frontend
npm ci
npm run build
cd ../backend
python -m uvicorn jobscope.main:app --host 127.0.0.1 --port 8765
```

前端开发使用 `npm run dev`，后端仍运行在 8765，Vite 将 `/api` 转发至后端。

## 数据与会话

- **Remotive**：公开远程岗位 API，明确显示海外/远程来源及原文链接。数据有延迟，不能作为国内平台接入成功的证明。连接器按源缓存并过滤查询，不高频轮询。
- **巨潮资讯**：通过 POST 接口查询公司公告，保存标题、发布时间和披露链接。在资料库点击“提取报告正文”可读取官方 PDF，保留页码；默认最多 60 页或 12 万字符，截断时明确提示。不含 OCR，扫描件可能无法提取。只有公告标题时不能声称取得了营收、利润或员工总数。
- **BOSS 接口**：无有效环境时可能返回 `code 37`。应用显示验证状态，不能把它当成零条岗位。
- **BOSS 浏览器**：安装可选浏览器依赖后，启动项目专用 Chrome，由你在该窗口登录并完成所需验证，再触发浏览器采集。会话保存在专属目录，不要求把 Cookie 贴进聊天。不保证站点长期可用或不会识别自动化。
- **完整岗位职责**：列表采集后，在岗位详情点击“读取完整职责”，或在“数据与采集 → 完整岗位职责”批量补全。通过已登录浏览器读取对应岗位页面的可见正文，保存原始链接、读取时间和证据快照。后台逐条保存，跳过已完成岗位；遇登录、人工验证或连续读取失败会暂停。再次执行可继续。只有列表摘要的 BOSS 岗位暂不能评估适配。详情页的公司介绍单独标记为平台企业自述。
- **手动导入**：可粘贴岗位和公司资料。来源标记为用户材料，不能冒充独立核验。

接口优先；依赖浏览器环境时由页面触发请求、监听结构化响应。真实页面结构和接口可能变化，连接器会返回明确失败状态。用户导入的链接用于出处，不让服务任意抓取内网或本机资源。

## 简历、适配与聊天

在“我的简历”可选择或拖入 PDF、Word `.docx`、TXT、Markdown、`facts.yaml` / `.yml` 文件（单文件不超过 10 MB）。文件在本机自动提取文字，先预览，再应用到编辑区，核对后保存到本地；导入或取消不会改变已保存的简历。PDF 最多 50 页，提取文本最多 100,000 字符；扫描件需先 OCR，受密码保护的文件需先解除密码，旧 `.doc` 请在 Word / WPS 另存为 `.docx`。不保留上传原文件，不调用外部模型做文本提取。也可直接粘贴纯文本或 ResumeLoom 的 `facts.yaml`。档案中的确认状态会影响可用事实。没有模型配置时只提供词项匹配，不生成综合分数；配置模型后逐项提取 JD 要求、关联个人事实，再由代码按维度计算分数与证据覆盖率。引用不存在、原文无法定位或覆盖率低于 60% 时不会生成有效总分。模型映射仍需核实，分数不是录用概率。

默认没有模型密钥。此时聊天只提供**资料检索摘录**，不会伪装成模型已经完成推理。在左侧“模型设置”选择 API 服务和渠道（OpenAI、Anthropic、DeepSeek、阿里百炼、火山方舟、智谱、月之暗面、硅基流动或自定义），填入 API 密钥，点击“获取模型列表”，搜索并选择模型，再测试、保存即可生效，无需重启。渠道会预填地址和协议；自定义渠道支持 Base URL 或完整端点，预设渠道地址可在高级设置中修改。对话与分析模型、语义检索模型分别配置。对话、查询规划与适配分析支持 OpenAI Chat Completions 和 Anthropic Messages 两种协议；向量模型使用 OpenAI Embeddings 或本地缓存。在线列表不代表全部模型都有调用权限，列表接口不可用时可使用预设参考或直接输入模型 ID 后测试。火山方舟部分模型需填写控制台接入点 ID。测试只发送固定文本，使用尚未保存的表单，不发送岗位或简历。

密钥保存在本地 SQLite 数据库中，不加密；读取设置只返回是否已设置。密钥留空保留原值，勾选可清除。保留旧密钥时不允许变更服务地址，避免将旧服务凭证发送至新地址。本地保存的配置优先于启动环境，包括显式禁用；已经开始的请求保持原配置，后续请求使用新配置。

仍支持通过启动环境提供初始配置：

```powershell
$env:JOBSCOPE_LLM_URL = 'https://你的服务地址/v1/chat/completions'
$env:JOBSCOPE_LLM_MODEL = '你的模型名'
$env:JOBSCOPE_LLM_KEY = '你的密钥'
.\start.ps1
```

URL 是完整的 Chat Completions 兼容端点；支持 HTTPS 或本机 HTTP 模型服务。保存后不会将密钥原文读回前端。调用外部模型会发送选定的简历材料和证据，配置服务前应确认你愿意交给该供应商处理。

对话分为三个独立范围：

- **岗位对话**：在岗位详情下方，只检索当前岗位的证据及同一公司的补充资料。同样采用流式工作区，左侧保存该岗位的历史会话；默认收起会话栏，点 « 可展开。
- **公司对话**：在公司资料库确认一个精确主体，只检索该公司的全部已保存岗位和公司证据。品牌、集团、子公司不会自动合并。布局与全局对话一致：左侧保存该公司的历史会话，回答边生成边上屏、可停止，函数调用与引用可展开，消息可编辑重跑或删除；刷新页面或切走再回来会继续接上未完成的运行。切换公司会另开新会话，旧会话仍在左侧列表里。通用 Agent（工具调用 / MCP / Skills）只在全局对话提供，公司对话固定为资料研究模式。
- **全局对话**：独立导航入口，允许检索本项目全部已保存的岗位和公司资料。引用显示公司与来源，方便比较。

服务端将会话 ID 绑定到固定范围，并保存最近 12 条历史消息；跨范围复用会话会被拒绝，客户端提交的历史不参与回答。等待中的旧回复不会进入切换后的公司或新建对话。三个对话页共用同一套工作区组件，会话列表按范围分别读取（`/api/conversations?scope=global|company|job`），页面内记住各范围最后一次会话，切走再回来会接上；生成中的运行由服务端继续，回到页面会重新挂接事件流。当前没有多用户账号和权限系统，这些范围是个人工作区的上下文隔离。

模型回答受所选资料范围约束，并验证返回引用 ID 属于当前范围。每次检索返回相关证据片段，不代表已完整审阅全库。引用存在不代表语义一定正确，重要结论仍需展开原文核对。网页和用户材料作为数据，不作为操作指令。

## 分页与资料浏览

岗位档案默认 20 条/页，来源档案、岗位证据和采集记录默认 10 条/页。分页在服务端执行，筛选后重新计数，从第一页展示。页面显示条目范围、总数、页码及上下页，来源档案上下均有翻页入口。岗位概览只返回有限的资料预览，完整资料在“证据资料”分页浏览。

公司资料库将“来源档案”和“公司对话”拆开，筛选提示与已锁定的对话范围各自显示。来源档案面板内可直接搜索标题与正文，输入即查，无需先点“查询资料”；空格分隔的多个词必须同时命中，命中的关键词会高亮，正文命中处会截出上下文片段。公司主体仍按精确匹配筛选，品牌、集团、子公司不会自动合并。桌面端来源档案采用紧凑分列，手机端自动堆叠。标签可用方向键及 Home / End 切换。

## 研究 Agent 升级

聊天现在先生成类型化计划，再调用范围内证据检索和结构化薪资工具。索引使用 SQLite FTS5 / BM25、中文领域词扩展，支持真实 embedding 余弦召回与 RRF 融合。历史原文保留，岗位查询优先当前快照；片段带字符偏移和 PDF 页码。薪资数量基于全部筛选岗位，最多展示 8 个样本，未知与招聘报价口径单独列出。回答下可展开执行记录；来源页支持同步、重建和分批构建向量。

默认使用 BM25，不需要模型。在“模型设置 → 语义检索模型”可以选择兼容 API 或本地缓存模型，保存后到“数据与采集”构建语义向量。本地模型只读取已缓存文件，需要安装可选依赖。也可以用命令行配置：

```powershell
pip install -r requirements-research.txt
.\start.ps1 -LocalEmbeddingModel 'BAAI/bge-small-zh-v1.5'
# 在“数据与采集”点击“构建语义向量”，之后查询自动融合
```

也支持完整的远端 embeddings 兼容端点：`JOBSCOPE_EMBEDDING_URL`、`JOBSCOPE_EMBEDDING_MODEL`、`JOBSCOPE_EMBEDDING_KEY`。远端模式会发送索引正文；本地模式不会向外发送正文。更换模型权重应使用新的模型路径/版本标识，避免复用旧向量。未构建或服务失败会明确回退 BM25。当前语义阈值按本次 BGE 小模型校准，不能假设更换模型后同样有效。

可复现检索对比：

```powershell
.venv\Scripts\python.exe evals\run.py --check
# 配置真实Embedding且已缓存模型后：
.venv\Scripts\python.exe evals\run.py --dense --check
```

报告写入 `output/research-evaluation*.json`，评测数据库与真实库隔离。合成集评测检索与范围，不评价生成回答质量。架构、面试演示与已知边界见[工程讲解](../docs/proposals/jobscope-agent-interview.md)，实测结果见[升级验证记录](../docs/validation/jobscope-research-agent.md)。

### 全局通用 Agent、MCP 和 Skills

在“全局对话 → 对话模式”选择“通用 Agent”。资料研究模式沿用原检索流程；通用模式可以回答一般问题，并连续调用工具完成任务，需要支持工具调用的模型。OpenAI Chat Completions 与 Anthropic Messages 均有原生工具适配。模式切换会新建对话，公司与岗位隔离对话不加载扩展。

内置项目检索、证据正文分页读取、全库薪资聚合、已确认简历事实读取。点击左侧独立的“Agent 扩展”进入管理页，也可从全局对话点击“管理 MCP 与 Skills”。页面分“市场 / MCP 工具 / Skills”三个视图：管理页为主从布局，左侧列表选中后，测试、工具授权、编辑、导出都在右侧详情完成。

**市场**：精选目录离线可用，收录约 12 个常用 MCP 服务（标注官方/社区、是否需要密钥）和若干自带的求职 Skills（面试演练、JD 拆解、公司研究简报、谈薪准备等），可一键添加或“基于此创建”改成自己的版本。在搜索框输入 2 个以上字符会**实时检索**：MCP 走 npm 注册表（关键词自动附加 mcp，最多 12 条），Skills 走 GitHub 仓库搜索（免凭证、自动附加 skill、定位仓库内 SKILL.md 并校验 frontmatter，最多 8 条，带 Star 数与来源仓库）；结果本机缓存 5 分钟。另可手动「刷新在线目录」获取推荐技能仓库（如 anthropics/skills）的 Skills，缓存 15 分钟，刷新失败会明确报错并保留精选目录。远程服务添加后仍需测试与授权；stdio 条目测试时会启动本地命令，请只添加信任的服务。

**MCP 连接**：支持远程 Streamable HTTP、旧版 SSE 和本机 stdio 三种传输；认证支持 Bearer 令牌与自定义请求头（值只保存不回显，Authorization 二选一）。粘贴常见 `mcpServers` 或单连接 JSON 自动填表，支持 `type: "sse"` 与自定义头。保存后点击“测试并发现工具”，选择允许调用的工具，再启用连接。工具默认逐次展示参数并确认，可按工具授权自动执行。读取过简历的会话在外部调用前仍需确认。连接可导出为通用 `mcpServers` JSON（凭证不导出，仅保留键名占位）。

**Skills**：支持粘贴 SKILL.md、上传 .zip 压缩包或选择本地文件夹导入多文件 Skill。SKILL.md 须有 YAML name/description，可选 category/author/keywords/icon 元数据；文本资源（≤20 个文件、单个 ≤60000 字符）随 Skill 保存，Agent 通过 `skill_resource` 工具按清单分页读取；脚本文件仅登记路径，不执行、不保存内容。同名重新导入会覆盖旧版本，导出为 .zip（含 SKILL.md、文本资源与清单，不含脚本内容）。

执行过程展示工具动作、耗时、失败和引用。每次最多8轮模型调用、12次工具、48000字符工具结果，达到上限后停止。MCP结果不会自动写入公司证据库。凭证保存在本机数据库且不加密，页面不回读；本地MCP进程具有当前系统用户权限。MCP 暂不提供 OAuth 交互与自定义 cwd/timeout 字段，导入时会明确提示。
